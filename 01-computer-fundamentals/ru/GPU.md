GPU — Graphics Processing Unit - устройство с совершенно другой философией: делать один и тот же простой тип задачи, но сразу тысячами копий параллельно

----------------------------------------------------------------------

1. Зачем вообще понадобился отдельный процессор для графики

Вспомни из заметки cpu.md: CPU отлично справляется с последовательными, разнообразными задачами — сегодня он выполняет логику программы, завтра открывает файл, послезавтра считает формулу в таблице. Это требует гибкости, и CPU за неё платит: у него относительно немного ядер (units), зато каждое ядро очень "умное" — с сложным управлением, предсказанием переходов, большим кэшем на ядро.

Но есть класс задач, где эта гибкость просто не нужна, а нужно совсем другое — скорость на масштабе. Классический пример — рендеринг изображения на экране.

Экран современного монитора состоит из миллионов пикселей (например, 1920×1080 = больше 2 миллионов пикселей). Чтобы отрисовать один кадр, нужно посчитать цвет каждого из этих пикселей. И вот ключевой момент: расчёт цвета одного пикселя почти никак не зависит от расчёта цвета соседнего пикселя — это, в отличие от многих задач CPU, задача, которая идеально делится на тысячи одинаковых, независимых друг от друга кусочков.

Если бы этим занимался CPU с его 8-16 ядрами — он бы считал пиксели более-менее по очереди, пусть и очень быстро. А GPU устроен так, что может взять и посчитать тысячи пикселей буквально в одно и то же время.

Аналогия: CPU — это несколько высококвалифицированных инженеров, каждый из которых может спроектировать что угодно, от моста до ракеты, но по одному проекту за раз. GPU — это огромный склад с тысячами простых рабочих, каждый из которых умеет делать только одну простую операцию, зато все они красят миллион одинаковых заборов одновременно.

-----------------------------------------------------------------------

2. Ключевая архитектурная идея: SIMD и массовый параллелизм

Разница между CPU и GPU — это не просто "у GPU больше ядер". Это разница в самой философии вычислений.

CPU: MIMD (упрощённо)

Ядра CPU относительно независимы — одно ядро может выполнять одну программу, другое — совершенно другую, в своём темпе, со своей логикой.

GPU: SIMD (Single Instruction, Multiple Data)

Ядра GPU объединены в группы, и все ядра в группе выполняют одну и ту же инструкцию одновременно, но каждое — над своим кусочком данных.

CPU (упрощённо):
Ядро 1 → делает задачу A
Ядро 2 → делает задачу B  (совсем другую)
Ядро 3 → делает задачу C  (ещё одну другую)

GPU (упрощённо):
Ядро 1    ┐
Ядро 2    │
Ядро 3    ├── все выполняют ОДНУ И ТУ ЖЕ инструкцию,
Ядро ...  │   но каждое — для своего пикселя/элемента данных
Ядро 5000 ┘

Именно поэтому у GPU счёт ядер (или, точнее, более простых вычислительных блоков — их часто называют CUDA cores у NVIDIA или stream processors у AMD) идёт на тысячи, в то время как у CPU — на единицы-десятки. Но эти "ядра" GPU гораздо проще устроены и не умеют того, что умеет полноценное ядро CPU — они заточены именно под однотипные, массово-параллельные вычисления.

-------------------------------------------------------------------------

3. Из чего состоит GPU
Ядра (CUDA cores / stream processors)

Простые вычислительные блоки, аналог сильно упрощённого ALU из заметки cpu.md — умеют быстро делать базовую арифметику (в первую очередь — операции с плавающей точкой, то есть с дробными числами, что критично для расчётов освещения, цвета, геометрии).

VRAM (Video RAM) — собственная память GPU

У GPU есть своя отдельная память, физически расположенная рядом с ним на видеокарте, а не общая оперативная память компьютера (RAM из заметки ram.md). Она называется VRAM.

Зачем нужна отдельная память, если уже есть RAM? Потому что GPU обрабатывает огромные объёмы данных (текстуры, геометрию сцены, кадровые буферы) с гигантской скоростью, и если бы ему приходилось каждый раз лезть за этим через шину в обычную системную RAM — расстояние и более узкий канал связи стали бы узким местом. VRAM физически расположена в миллиметрах от самих вычислительных ядер и подключена к ним очень широкой шиной — поэтому обладает огромной bandwidth (вспомни это понятие из заметки ram.md), гораздо выше, чем у обычной системной RAM.

Память кадрового буфера (Framebuffer)

Часть VRAM отведена под framebuffer — это, по сути, "холст", на котором GPU собирает готовое изображение, которое затем построчно передаётся на монитор через кабель (HDMI/DisplayPort). Формируется он десятки раз в секунду — отсюда понятие частоты обновления кадров (FPS — Frames Per Second).

Шина связи с материнской платой: PCIe

Видеокарта (в случае дискретного GPU, см. ниже) подключается к материнской плате через слот PCIe, который мы уже упоминали в заметке motherboard.md. Это широкий, быстрый канал связи, по которому CPU передаёт GPU данные и команды, что нужно отрисовать, а GPU в ответ передаёт готовое изображение (или его отправляет напрямую на монитор).

-----------------------------------------------------------------------------

4. Дискретный vs интегрированный GPU
Дискретный (discrete/dedicated) GPU

Отдельная физическая видеокарта, со своим собственным чипом и собственной VRAM, подключаемая через PCIe-слот. Это то, что обычно и называют "видеокарта" — например, отдельные модели NVIDIA GeForce или AMD Radeon.

Плюсы: значительно выше производительность, собственная быстрая VRAM, не отнимает ресурсы у CPU/RAM. Минусы: дороже, потребляет больше энергии, требует больше места и охлаждения, физически греется сильнее.

Интегрированный (integrated) GPU

GPU, встроенный прямо в тот же чип, что и CPU (или физически расположенный очень близко на той же плате). У такого GPU обычно нет собственной VRAM — вместо этого он использует часть обычной системной RAM, "одалживая" себе кусок памяти компьютера.

Плюсы: дешевле (не нужно покупать отдельную видеокарту), меньше энергопотребление, не занимает отдельное место, достаточно для обычных задач (браузер, видео, офисные программы, лёгкие игры). Минусы: заметно ниже производительность, делит с CPU одну и ту же RAM (а RAM обычно медленнее выделенной VRAM и её пропускной способности не хватает под тяжёлые нагрузки), делит с CPU общее тепловыделение.

Пример: Apple Silicon (M1/M2/M3) и большинство процессоров Intel/AMD для ноутбуков имеют интегрированную графику прямо в чипе CPU. А отдельная видеокарта NVIDIA RTX или AMD Radeon RX, которую покупают отдельно и вставляют в PCIe-слот — это дискретный GPU.

5. Для чего используется GPU кроме графики: GPGPU

Оказалось, что тот же принцип "одна инструкция, тысячи параллельных данных", идеально подходящий для расчёта пикселей, точно так же идеально подходит и для многих других задач, где нужно применить одну и ту же простую математическую операцию к огромному массиву чисел одновременно.

Это направление называется GPGPU (General-Purpose computing on GPU) — использование GPU не для графики, а для универсальных вычислений. Самый яркий пример сегодня — обучение и работа нейросетей (включая большие языковые модели вроде тех, что стоят за такими ассистентами, как этот).

Почему нейросети так хорошо ложатся на архитектуру GPU: в основе большинства нейросетевых вычислений лежат операции над матрицами — умножение огромных таблиц чисел друг на друга. Умножение матриц — это ровно тот тип задачи, который прекрасно разбивается на тысячи одинаковых, независимых мелких операций (перемножить пару чисел, сложить с накопленной суммой) — то есть то же самое SIMD-параллельство, что и при расчёте миллионов пикселей на экране.

Именно поэтому современные GPU (особенно от NVIDIA, благодаря их программной платформе CUDA, позволяющей писать не только графический, но и универсальный параллельный код) стали основным "рабочим инструментом" в области машинного обучения — CPU физически не способен угнаться за GPU в задачах такого рода, потому что архитектурно заточен под совсем другой тип работы (последовательные, разнородные задачи, а не миллионы одинаковых мелких операций сразу).

Расчёт пикселя на экране:  цвет = f(координаты, свет, текстура) — для каждого из миллионов пикселей
Шаг обучения нейросети:    результат = f(веса, входные данные)  — для миллионов чисел в матрицах

Оба случая: одна и та же простая операция, применённая параллельно к огромному количеству данных

6. GPU и остальная система: как всё связано

Возвращаясь к общей картине из предыдущих заметок:

CPU (cpu.md) решает: "что вообще нужно отрисовать в этом кадре"
    (логика игры, положение объектов, что видно, а что нет)
        ↓
CPU передаёт GPU команды и данные через шину PCIe (motherboard.md)
        ↓
GPU загружает нужные текстуры/геометрию из VRAM
(своей собственной быстрой памяти — параллель с RAM из ram.md,
 только физически отдельной и предназначенной именно для GPU)
        ↓
Тысячи ядер GPU параллельно считают цвет каждого пикселя
        ↓
Готовый кадр собирается во framebuffer
        ↓
Изображение построчно передаётся на монитор
        ↓
Процесс повторяется десятки раз в секунду (FPS)

Важно понимать: CPU и GPU не конкурируют друг с другом, а дополняют друг друга, каждый в своей сфере — ровно так же, как в предыдущих заметках мы видели, что RAM, ROM и Storage не заменяют, а дополняют друг друга, каждый жертвуя чем-то одним ради выигрыша в другом. CPU нужен там, где важна гибкость и последовательная логика; GPU — там, где нужно применить одну и ту же простую операцию к огромному количеству данных одновременно.

7. Итоговое сравнение: CPU vs GPU
	CPU	GPU
Количество ядер	Единицы – десятки	Тысячи (более простых)
Сложность одного ядра	Высокая (сложное управление, предсказание переходов)	Низкая, каждое ядро простое
Философия	Последовательные, разнородные задачи	Массово-параллельные, однотипные задачи
Тип памяти	RAM (общая системная память)	VRAM (собственная, очень быстрая)
Классическая задача	Логика программы, ОС, разнородные вычисления	Рендеринг графики, обучение нейросетей, матричные вычисления
Аналогия	Несколько универсальных инженеров	Тысячи рабочих, красящих один и тот же забор параллельно
